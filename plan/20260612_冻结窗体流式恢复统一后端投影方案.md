# 20260612_冻结窗体流式恢复统一后端投影方案.md

## 需求
- 修复聊天窗体被冻结/失焦后恢复时，流式消息偶发显示双消息的问题。
- 恢复当前会话时，不再由前端分两轮自行拼装“正式消息 + draft + stream cache”。
- 后端提供单一恢复入口，直接返回“当前前台应该显示的最终消息投影”。
- 优先用最小改动收口现有逻辑，尽快降低双消息概率，并减少前端恢复时序压力。

## 问题现状
- 前端恢复当前会话时，先拉会话轻量快照，再单独拉运行态快照，再结合本地 draft 和 stream cache 自行恢复流式投影。
- 前端存在多条恢复入口：会话切换恢复、窗口重新激活恢复、流式重绑恢复。
- 当前 snapshot 恢复里会在 runtimeState=assistant_streaming 且后端快照没有 draft 时，强行保留冻结前旧 draft。
- 当前 overlay 只依赖 persistedAssistantMessageId 去剔除正式消息，无法覆盖所有“正式 assistant 已落库但 draft 仍被复活”的时序。

## 已钉死的 bug 结论
- 双消息不是 key 冲突，而是同一轮 assistant 的两种表现同时进入显示列表：
  - 前端 draft：__draft_assistant__:{gen}
  - 后端正式 assistant：真实 message id
- 根因是“恢复显示真相”被拆分在前端多处逻辑中，缺少后端 authoritative projection。
- 现状下，只要恢复时序落在：
  - 正式 assistant 已在快照里
  - 旧 draft 又被前端保留
  - stream cache 还表明当前轮有可见进度
  就可能出现双消息。

## 方案边界
- 这次不重做整套流式协议。
- 不改实时流式 delta 主链，只改“冻结/恢复当前会话”的恢复真源。
- 不继续在前端追加更多猜测型 dedupe 规则。
- 保留现有 bind_active_chat_view_stream 与 stream-rebind-required 作为流通道补连机制。

## 推荐实现
- 后端沿用现有前台轻量快照命令 `get_foreground_conversation_light_snapshot`，新增 `resumeProjection` 恢复模式。
- 普通会话切换、历史加载、回退刷新默认不启用 `resumeProjection`，保持现有行为。
- 启用 `resumeProjection` 时，后端统一读取：
  - 当前会话轻量快照
  - 当前会话 runtime snapshot
  - 当前会话 stream cache
- 后端输出：
  - `messages`：恢复后前台应显示的最终消息投影
  - `runtimeState` / `hasMoreHistory`
  - `streamCache`
  - `shouldBindStream`
  - `resumeProjectionAuthoritative`
- 后端在构造 `messages` 时，自己完成：
  - 若当前流式无可见进度，只返回正式消息
  - 若当前流式有可见进度，则按 runtime stream cache 生成单一 assistant 流式投影
  - 若已存在 persistedAssistantMessageId，对应正式 assistant 不再同时出现在 `messages` 中
  - 清掉快照里已有的旧 `__draft_assistant__:*`，避免旧草稿复活
- 前端恢复当前会话时，改为：
  - 只调用带 `resumeProjection=true` 的轻量快照
  - 直接采用后端返回的 `messages` 渲染
  - 若 `shouldBindStream=true`，再绑定流式通道并用同一份 `streamCache` 恢复前端运行态
- 前端在 `resumeProjectionAuthoritative=true` 时停用以下自拼逻辑：
  - `applyConversationSnapshot` 中“保留旧 draft 再 overlay”逻辑
  - `applyConversationSnapshot` 中自动二次读取 runtime snapshot 的逻辑
  - `restoreForegroundConversationProjection` 里“先轻量快照、再运行态恢复”的两段式恢复

## 最小实施顺序
1. Rust 扩展 `ForegroundConversationLightSnapshotInput/Output`，新增恢复投影字段。
2. Rust 实现 projection 合成函数，复用现有轻量快照和 runtime snapshot 读取。
3. 前端 `restoreForegroundConversationProjection` 改为只请求一次权威恢复快照。
4. 前端 `applyConversationSnapshot` 在权威恢复快照下停用旧 draft 复活和二次 runtime 恢复。
5. 增加最小单测，钉死“已持久化半消息 + 旧 draft + 新投影”不能并存。

## 验收标准
- 窗体冻结/失焦后恢复当前流式会话时，前台最多只显示一条当前 assistant 结果，不再出现 draft 与正式 assistant 并存。
- 非流式会话恢复显示不回归。
- 远程流式重绑仍能继续接收后续 delta。
- 前端恢复链路减少为一次 authoritative snapshot + 可选 bind stream。
