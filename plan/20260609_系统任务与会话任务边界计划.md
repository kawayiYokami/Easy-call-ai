# 系统任务与会话任务边界计划

状态：已实现，待用户确认归档

## 用户结论

本轮最终口径：

- 任务是调度触发器，不是执行结果追踪器。
- 任务触发后的执行结果应该回到对应会话；系统任务的结果回到 `P-ai系统`。
- 一次性任务的职责是发起调度。发起调度时任务立即结束，不等待模型执行完成，也不回填模型结论。
- 定时任务每次到点只触发一次后续调度，不接管后续执行结果。
- 定时任务不能切换为一次性任务。
- 系统会话固定叫 `P-ai系统`，不允许改名。
- 系统会话头像固定使用系统人格头像，不跟随最后一条消息变化。

## 当前实现摘要

### 系统会话

- 固定 ID：`system-notification-conversation`。
- 固定显示名：`P-ai系统`。
- 固定头像来源：`system-persona` 人格头像。
- 后端归一化系统通知会话时会把标题恢复为 `P-ai系统`。
- 前端会话菜单隐藏系统会话重命名入口，后端也不会保留用户改名结果。
- 系统会话不作为普通聊天上下文来源。

### 任务归属

不新增 `task_scope` 字段，任务归属只看 `conversation_id`：

- `conversation_id == system-notification-conversation`：系统任务。
- `conversation_id` 指向有效普通会话：会话任务。
- 空 `conversation_id`：按旧数据兼容，归一化为系统任务。
- 非空但找不到普通会话：普通会话任务绑定丢失，任务失败结束，不回退到系统会话，也不显示成“未关联会话”。

`target_scope` 只保留 desktop/contact 等执行目标含义，不再参与判断系统任务或会话任务。

### 一次性任务

- 一次性任务到点进入调度流程时，立刻标记为 `completed`。
- 这个完成只表示“任务已经发起调度”，不表示模型已经完成工作。
- 成功投递、投递失败、会话忙碌、队列繁忙等调度结果写入运行日志或对应会话，不把模型执行结果写回任务记录。
- 历史数据迁移会把已经触发过、且触发时间不早于计划时间的一次性 active 任务补成 completed。
- 如果未来一次性任务带有旧的 `last_triggered_at_utc`，迁移不会误完成它。

### 定时任务

- 定时任务保持 active，通过 `last_triggered_at_utc` 推进下一次触发时间。
- 定时任务每次只负责投递一次调度事件。
- 定时任务不等待执行结果，不把模型执行结果写回任务记录。
- 后端拒绝把已有定时任务更新为一次性任务。
- 前端配置页和聊天任务编辑弹窗都禁用“定时任务切换到一次性”的操作。

### 系统任务调度

- 系统任务不读取 `P-ai系统` 会话正文。
- 系统任务触发时创建独立异步委托。
- 系统任务不会因为同一轮已有其他系统任务而被去重跳过。
- 独立委托的状态和回答归到 `P-ai系统`。
- 系统任务提示词不再要求模型调用任务完成工具。

### 会话任务调度

- 会话任务只投递到绑定的普通会话。
- 绑定会话不存在或不可用时，任务失败结束，不 fallback 到系统会话或主会话。
- 会话忙碌、队列不空、并发上限等跳过原因仍写运行日志；一次性任务在发起调度口径下会结束，定时任务会推进下次触发。
- 会话任务提示词不再要求模型调用任务完成工具。

### 编辑和列表 UI

- 聊天侧栏任务 tab 只展示 active 任务，并按普通会话或 `P-ai系统` 分组。
- 不再显示“未关联会话”分组。
- 任务编辑弹窗新增删除按钮和确认弹窗。
- 删除任务后广播 `easy-call:task-deleted`，侧栏同步刷新。
- 新建任务必须带有效会话 ID；从 `P-ai系统` 创建时写入固定系统会话 ID。

## 兼容边界

- 数据库中的 `completion_conclusion` 字段暂时保留，用于旧数据、手动完成入口和任务自身失败原因兼容。
- 调度链路不再把模型执行结果写回 `completion_conclusion`。
- 已经完成的一次性任务不会再接受后续隐藏的任务完成工具结果回填。
- 旧的空 `conversation_id` 任务统一迁到系统会话，避免前端出现无归属任务。
