# 发布：v0.11.5

- 重构（chat）：删除代码审查报告页面（reports tab），「发起审查」入口移至更多菜单（委托下方）；审查结果已通过委托面板展示，报告页面冗余。
- 修复（chat）：远程联系人会话隐藏完整输入面板，改为只显示新建任务按钮的精简面板，与系统通知会话行为一致。

- 修复（goal/archive）：移除应用启动时扫描 active goal 并自动续跑的行为；发送前上下文整理取消未设计的“空闲 30 分钟且用量 30%”触发条件，仅保留强制阈值保护。
- 修复（goal）：用户手动中断当前回复后暂停会话 goal 自动续跑，下一条非 goal 调度再恢复；goal 续跑消息改由系统人格发送，气泡仅显示短提示，完整续跑提示仅作为隐藏提示进入模型上下文。
- 功能（goal/delegate）：新增会话绑定 goal 机制与 `create_goal`/`update_goal` 工具，任务到点后启动委托并以 goal 续跑至完成；委托字段统一为 why/goal/todo，goal 工具常驻模型工具集，联系人专用工具仅在远程联系人会话附加。
- 功能（settings）：新增独立 Web 设置页；VS Code 侧边栏设置按钮打开桌面设置窗口，浏览器侧边栏设置按钮新开设置标签页；补齐设置页 JSON-RPC 桥接、长任务超时策略、更新进度同步和 WebSocket Origin 同源校验。
- 修复（chat）：引导消息打断流式回复时，前端按正式消息时间线合并 history flush、完成事件和后台补消息；过期轮次完成不会清掉当前流式缓存，避免出现双助理气泡同时流式、用户消息错位和旧回复追加到新消息后面。
- 修复（delegate）：`delegate` 工具模式改为 `wait/background`，明确 `wait` 可并发并等待结果；同批相同委托不再被重复调用熔断误停，停止父调度会级联中止同步委托；委托计时改由开始/完成时间前端派生，会话控制面板与右侧委托/工具审查卡片补齐清晰入口、图标和结果展示。
- 修复（chat）：调度启动后固化执行部门与人格，后端流式缓存携带 `departmentId/agentId`，前端草稿只从流式快照或正式消息继承说话人；缺失或消失的执行部门/人格会直接中断，不再兜底到助理部门，避免多窗口/切换会话时角色扮演回复显示成助理头像或名称。
- 优化（chat/sidebar）：新增会话控制面板整合工作目录与委托状态，远程/Web 端支持查看和打断委托，并将 Web 工作目录设置改为可手动输入与逐级浏览的目录选择器。
- 优化（config）：网络访问新增启用开关与自定义远程访问密码，关闭后 Web/IDE 桥服务会停止；远程地址优先筛选真实局域网网卡并避开常见虚拟网卡，远程侧边栏页面补齐 PAI 图标。
- 修复（chat）：本地文件 Markdown 链接统一由阅读侧边栏打开，支持 `path:line` 文件引用；普通 Web 侧边栏同样走内置阅读栏，仅 VS Code 扩展交给 VS Code 打开。
- 优化（chat）：聊天标题栏右侧阅读与委托入口改为常驻图标按钮，点击当前面板可收起，点击另一入口可直接切换并打开侧边栏。
- 功能（sidebar）：Web/VS Code 侧边栏改为复用桌面聊天左右栏、标题栏和输入面板，新增浏览器网络访问页、端口配置和远程访问密码；本机访问免密码，局域网/外网访问登录成功后才注册聊天广播客户端，并按访问端 viewer ID 处理会话占用。
- 修复（chat）：撤回/重新生成增加前端进行中保护，撤回弹窗的 apply_patch 可回滚判断改为后端预览真实备份记录，避免长会话工具历史在 UI 线程同步解析导致前端卡死或崩溃。
- 修复（chat）：请求体预览会话下拉复用会话显示标题解析，历史脏数据中标题等于 UUID 的会话会回退到摘要标题或时间标签，不再直接显示裸 ID。
- 修复（config）：部门配置页将 `leader` 识别为系统内置部门，主操作显示“恢复初始化”而不是“删除部门”，并支持恢复移除无关工具描述后的 leader 默认办事指南。
- 修复（chat）：调度流式过程中触发上下文压缩时，压缩 flush 事件会携带压缩前已落盘的 assistant checkpoint，并在内部重启前显式发送新一轮 `round_started`，避免界面临时只显示“压缩消息 + 新流式草稿”。
- 修复（chat）：上下文压缩/整理期间锁定当前会话输入与发送动作；若后端因竞态返回 queued，也会撤回临时草稿，避免同一条消息同时出现在队列和聊天正文。
- 修复（chat）：聊天窗口从后台恢复且后端流式已结束时，主动拉取前台轻量快照补齐最新消息，避免 WebView 后台节流漏掉完成事件后回答不显示。
- 修复（chat）：聊天窗口持久化记录最后打开的本地会话，浏览器/WebView 重新加载后优先恢复该会话；记录不存在时再回到系统通知会话，避免刷新后总是弹回系统会话。
- 优化（delegate）：调整内置 `delegate` 工具使用规则，明确有合适直属下级部门时优先委托，简单但繁琐且可独立描述的子任务适合委托；除非用户明确要求后台执行，否则默认同步等待结果，并要求主代理核验关键结论后再裁决。
- 优化（department）：重写内置 `leader` 部门办事指南，明确使用同步 `delegate` 协调下级部门，并要求核验下级关键结论后再最终回复。
- 修复（chat）：消息少于 3 条或正文少于 10K 的会话统一只显示删除入口；会话列表和“处理当前会话”弹窗不再展示归档/压缩动作，避免短会话点击后被后端拒绝。
- 修复（chat）：手动归档和归档预览只以 `conversationId` 入参解析会话，后端再从会话绑定部门派生执行人格与模型；前端点击、后端入口、拒绝原因和完成结果均补充归档日志，避免点击归档静默无反馈。
- 修复（chat）：消息仓库迁移预检不再把中断残留的 `building` manifest 当成启动阻塞异常；有旧会话 JSON 时直接重试迁移，目录内容完整时自动恢复为 ready，避免首次启动弹出误报。
- 功能（department）：新增内置预设部门 `leader`，默认使用助理人格，负责盘问需求、确定方案、拆解任务并指派下级部门；默认下级为助理部门与 `explorer`。
- 功能（task）：新建任务弹窗新增魔法棒优化按钮，可用快速模型把用户草稿结构化为完整任务草稿，自动回填标题、正文、一次性/定时模式、触发时间、重复间隔和结束时间；该主动优化请求不设置等待超时，并补充后端开始、完成、失败日志。
- 优化（model）：新增快速模型 JSON 请求 helper，传入提示词即可默认使用快速模型并返回解析后的 JSON，自动标题生成已切换复用该入口。
- 修复（task）：任务绑定系统通知会话时按系统任务处理并走独立异步委托；普通会话任务绑定会话丢失时直接标记失败，不再回退或显示为未关联会话。
- 修复（task）：一次性任务发起调度时立即完成，不再等待后续模型执行或把模型结果写回任务记录；历史已触发的一次性 active 任务会迁移为完成，未来任务不会被旧触发时间误完成。
- 修复（task）：定时任务禁止切换为一次性任务，后端更新校验和前端编辑入口同步拦截。
- 优化（chat）：系统通知会话固定显示为 `P-ai系统` 并使用系统人格头像，隐藏重命名入口，避免被最后消息或用户改名影响识别。
- 优化（chat）：任务编辑弹窗新增删除按钮和确认弹窗，删除后会同步刷新任务侧栏。
- 功能（chat）：会话左侧栏新增任务 tab，仅展示进行中的任务并按所属会话分组，点击任务可打开编辑弹窗保存标题、正文与调度。
- 功能（chat）：系统通知会话底部新增新建任务入口，支持一次性与定时任务切换，定时用一行重复间隔输入，范围覆盖每分钟到每月，任务正文前置并自动从正文生成默认标题。
- 优化（chat）：系统通知会话内发起委托时隐藏重复操作栏与审查快捷预设，但保留委托表单卡片边界，避免表单贴在输入区里不好识别。
- 优化（chat）：简化发起委托表单布局，委托内容正文前置为主输入区，背景与重点改为左右并排的辅助输入区。
- 修复（chat）：运行态指针归一到固定系统通知会话时同步确保系统通知会话分片落地，避免新配置或已分片数据只有固定 ID 指针但缺少实际系统通知会话；旧主会话仍保留为普通会话。
- 修复（chat）：将旧“主会话”语义切换为固定 ID 的“系统通知”会话；迁移时旧主会话保留为普通会话，系统通知会话新建并固定为通知接收器，禁止发言、工具栏、归档/删除/独立窗口等普通会话操作，底部仅保留发起委托与新建会话入口。
- 修复（delegate）：右侧栏委托状态改为打开时查询一次并由后端状态广播触发刷新，不再前端定时轮询或显示“正在加载委托状态”。
- 修复（config）：专家模型与部门模型解耦，部门仅默认引用 `role:expert`，不再在规范化、保存部门或聊天切换部门模型时反向覆盖专家模型设置。
- 优化（chat）：处理当前会话弹窗移除丢弃入口并精简压缩/归档说明；会话菜单的归档入口改为红色删除图标，同时归档反思只读取正文与记忆块，正文不足阈值时跳过反思。
- 修复（chat）：光速归档会立即标记会话为已归档并刷新会话列表与归档窗口，后台仅执行归档维护；空会话、无助理回复和过短会话会在归档前拦截，避免归档后被删除或列表残留。
- 修复（chat）：供应商请求返回真实用量并累加会话用量后立即推送标题栏上下文占用更新；工具续调估算用量不再广播到前端。
