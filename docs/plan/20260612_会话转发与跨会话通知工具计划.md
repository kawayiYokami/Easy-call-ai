# 会话转发与跨会话通知工具计划

## Summary
- 先在 `plan/20260612_会话转发与跨会话通知工具计划.md` 写入本计划，再开始任何实现。
- 扩展“多选消息转发到会话”能力，目标同时支持本地未归档普通会话和远程联系人会话。
- 新增两个内置工具：`get_session` 与 `inform_session`。
- `get_session` 未提供关键字时返回“本地未归档普通会话 + 远程联系人会话”；提供关键字时按标题、联系人、部门、人格做匹配过滤。
- `inform_session` 以系统助理身份向目标会话发送一条消息，正文固定为 `[会话·部门·人格]:内容`。
- 目标是远程联系人时，除写入其联系人会话外，还要把同一条内容推送到远端渠道。
- 实际实现已调整为“全局通知 helper 入队 + 后台异步投递”：工具调用方只负责入队并立即返回 `accepted`，后续由 helper 等待目标会话可用后再发送。
- `inform_session` 默认只投递，不自动触发目标会话继续跑 AI。

  - 计划内容以本方案为准，后续实现如有偏差，完成后再按实际情况修订并等待用户确认是否归档

  - 转发目标不再只传 `conversationId`，改为传完整目标信息：`kind`、`conversationId`、`remoteContactId?`
  - 本地目标展示“标题 / 部门 / 运行态”，远程目标展示“联系人会话标题 / 联系人 / 渠道”
- 前端编排
  - 扩展 [src/features/chat/composables/use-chat-conversation-actions-orchestrator.ts](/E:/github/easy_call_ai/src/features/chat/composables/use-chat-conversation-actions-orchestrator.ts)
  - 本地目标继续走现有 `forward_unarchived_conversation_selection`
  - 远程目标新增调用 `forward_selection_to_remote_im_contact`
  - 本地转发成功后切到本地目标会话；远程转发成功后切到对应远程联系人会话
- Rust 转发能力
  - 保留现有本地转发命令不变
  - 新增“选中消息转发到远程联系人会话”命令与 service
  - 从源本地会话提取选中消息，汇总为一条系统助理消息写入目标远程联系人会话
  - 该条消息内容改为交给全局通知 helper 异步投递到远端渠道，复用现有 `builtin_remote_im.rs` / `remote_im_send_content_payload`
  - 新消息使用 `role = "assistant"` 与 `speaker_agent_id = SYSTEM_PERSONA_ID`
- 新内置工具
  - `get_session`
    - 参数：`keyword?: string`
    - 返回字段至少包含：`session_id`、`kind`、`title`、`department_name?`、`persona_name?`、`remote_contact_id?`、`remote_contact_name?`、`channel_name?`、`updated_at`
    - 默认只返回本地未归档普通会话与远程联系人会话，不包含系统通知会话和委托子会话
    - 关键字匹配：
      - 本地：标题、摘要标题、部门名、人格名
      - 远程：会话标题、联系人显示名、渠道名、绑定部门名、绑定人格名
  - `inform_session`
    - 参数：`session_id: string`、`content: string`
    - 调用方当前会话作为来源，构造正文：`[会话·部门·人格]:内容`
    - 调用路径改为“入队后立即返回”，返回值带 `accepted=true` 与 `status=queued`
    - 后台 worker 轮询目标会话运行态；若目标会话正在 `streaming` / `organizing`，则等待可用后再投递
    - 目标为本地会话：后台写入会话并刷新概览/未读
    - 目标为远程联系人：后台写入联系人会话并外发到远端
    - 不自动触发目标会话继续推理
  - 工具注册
    - 在内置工具目录、运行时工具装配、前端工具 catalog 中注册 `get_session` / `inform_session`
    - 在部门权限目录中隐藏这类固定会话工具，和 `todo` / `plan` / `task` 一致
- 公共辅助逻辑
  - 新增统一的会话搜索 helper，供 `get_session` 和前端目标列表复用
  - 新增统一的通知正文构造 helper，避免“远程转发”和 `inform_session` 各写一套格式化逻辑
  - 新增进程内全局通知 helper
    - 单例 sender + 后台 worker 线程
    - `inform_session` 与“转发到远程联系人”统一走该 helper
    - helper 负责记录日志、等待目标会话可用、调用远端发送、回写目标会话消息与概览事件

## Test Plan
- Rust
  - 本地转发回归：`forward_unarchived_conversation_selection` 行为不变
  - 远程转发：转发到远程联系人后，请求立即返回；后台投递成功后，目标联系人会话新增 1 条系统助理消息，且远程发送被调用一次
  - `get_session`：
    - 空关键字返回本地普通未归档 + 远程联系人
    - 不返回系统通知会话和委托子会话
    - 关键字可分别命中标题、联系人、部门、人格

    - 调用时立即返回 `accepted`
    - 本地目标由后台落库，不触发 streaming

    - 目标不存在

## Assumptions
- “远程会话”明确指远程联系人会话，不是另一台 PAI 的本地会话
- `inform_session` 不需要 `title`
- 多选转发到远程时，按一条系统助理通知消息落库与外发，而不是逐条复制原消息
- 默认会话查询范围仅包含本地普通未归档会话与远程联系人会话
- 当前实现接受“调用方不等待最终送达结果”，只拿到入队成功；真正送达与失败由后台 helper 日志负责观测
