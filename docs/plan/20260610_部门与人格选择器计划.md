# 部门与人格选择器计划

## 背景

当前配置模型已经允许一个部门绑定多个人格：`DepartmentConfig.agentIds`。但多个入口仍把“部门”当成唯一执行目标，并在需要人格时取 `agentIds[0]` 或从当前 UI 状态推断。这会导致多人格部门下无法明确创建会话、委托或远程绑定的执行人格，也会破坏“会话创建后按原部门与人格继续执行”的稳定性。

## 目标

- 用户在需要选择执行身份的地方，统一选择“部门与人格”组合。
- 用户直接看到的是 `部门名 / 人格名` 组合；任务场景可用“负责人”作为字段名，但不新增独立业务实体。
- 配置结构继续保存逻辑部门和人格列表，不生成 `部门A-1` 之类真实部门。
- 会话创建后固定保存 `departmentId + agentId`，后续调度只使用会话绑定身份。
- 人格后来从部门列表移除时，旧会话仍可按原部门与人格继续执行；部门或人格本体被删除时才中断。

## 非目标

- 本次不重构部门配置数据结构，不生成派生部门。
- 本次不改变部门树、模型配置、权限配置的存储语义。
- 本次不迁移历史会话 ID，仅修正新入口和运行时校验。

## 用户体验

所有需要选择执行身份的下拉统一为：

```text
部门与人格
角色扮演部 / 知更鸟
角色扮演部 / 助理
研究部 / 探索者
```

单人格部门也显示为 `部门名 / 人格名`，保证用户看到的选项形态一致。

## 影响范围

### 共用前端能力

- 新增共用选项构造工具，将 `departments + personas + apiConfigs` 展开为 `{ departmentId, agentId, label }`。
- 新增共用选择器组件，使用 `v-model:department-id` 与 `v-model:agent-id` 输出组合。
- 组件只负责选择，不写配置、不创建会话、不推断当前会话。

### 新建会话

- 桌面聊天窗口、Web/侧边栏新建会话入口均改用共用选择器。
- 提交创建会话时必须传明确 `departmentId + agentId`。
- 后端创建时校验部门存在、人格存在、且创建时人格属于该部门。

### 调度

- 调度启动继续从会话绑定身份写入 `runtime_context.executorDepartmentId/executorAgentId`。
- 调度运行时校验部门存在、人格存在。
- 对历史绑定会话，不再要求人格仍在部门 `agentIds` 内，避免组织关系调整后旧会话漂移或中断。

### 委托

- 已有委托存储结构包含 `source_department_id/source_agent_id/target_department_id/target_agent_id`，结构可复用。
- 用户手动委托、选中内容委托、代码审查委托入口需要明确目标人格，避免继续取目标部门第一个人格。
- LLM `delegate` 工具协议要求同时提供 `department_id + target_agent_id`，后端校验目标人格属于目标部门。

### 任务

- 任务记录新增 `departmentId + agentId` 绑定。
- AI 通过 task 工具创建任务时，按当前执行者的部门与人格写入任务。
- 手动任务编辑器可选择负责人；未显式选择时，后端仅在创建/保存时从绑定会话或默认助理推导一次并固化。
- 任务触发调度时直接读取任务绑定的部门与人格，发起普通任务事件，不生成委托记录。

### 远程 IM

- 远程联系人绑定升级为“部门与人格”组合，并持久化 `boundDepartmentId + boundAgentId`。
- 联系人设置页使用共用选择器，列表展示实际绑定人格。
- 调度时读取联系人固化身份；旧联系人缺少人格时只在绑定/会话确保阶段推导一次并写回。

### 归档与记忆

- 多人格部门后，归档记忆归属不应要求部门只能绑定一个人格。
- 优先使用会话自己的 `agentId` 作为归属人格；部门不存在或人格本体不存在时失败。

## 实施步骤

1. 新增共用类型与工具：展开部门与人格选项，统一过滤不可用部门、用户人格、缺失人格。
2. 新增 `DepartmentPersonaSelect` 组件。
3. 新建会话入口接入组件，并确保提交 `departmentId + agentId`。
4. 后端创建会话校验创建时组合合法，去掉创建时无人格取第一个人格的路径。
5. 调度校验调整为运行时只要求部门和人格本体存在，不要求仍属于部门。
6. 提示词、归档、分支等会话周边入口只认会话固化 `agentId`，缺失或不可用时失败。
7. 手动/选中内容委托入口和 LLM delegate 工具改为明确目标人格；后端接口接受并使用 `targetAgentId`。
8. 远程 IM 联系人设置和运行时绑定补齐 `boundAgentId`。
9. 任务记录、AI task 工具和任务调度补齐 `departmentId + agentId`，触发时不再生成委托。
10. 归档 owner 解析改用会话 `agentId`。
11. 跑最小相关检查。

## 验证点

- 多人格部门在新建会话下拉中展开为多个 `部门 / 人格` 选项。
- 选择第二个人格创建会话后，会话保存该 `agentId`，发送调度使用该人格。
- 从部门中移除该人格后，旧会话仍可继续调度。
- 删除人格本体或部门本体后，旧会话调度失败并提示明确原因。
- 选中内容委托目标可明确选择人格，不再默认为部门第一个人格。
- LLM `delegate` 工具缺少 `target_agent_id` 时失败。
- 远程 IM 联系人可保存并展示 `部门 / 人格` 绑定。
- AI 创建的任务保存当前执行者 `departmentId + agentId`；任务触发按任务绑定身份发普通任务事件，不生成委托。
- `pnpm typecheck`、`cargo check`、`cargo test --no-run` 和相关目标测试通过。
