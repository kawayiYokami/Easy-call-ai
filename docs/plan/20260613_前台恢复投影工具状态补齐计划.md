# 前台恢复投影工具状态补齐计划

## 背景

- 当前前台恢复链路已经改为由后端输出 authoritative resume projection。
- 运行中工具的状态文案与状态枚举已经写入后端 `ConversationStreamRuntimeCacheSnapshot`。
- 但恢复投影构造 synthetic assistant draft 时，只投影了 `_streamBlocks`，没有把工具状态一起投影到消息 `provider_meta`。
- 前端在 `resumeProjectionAuthoritative=true` 的恢复路径下，会直接采用这条恢复消息，不再额外走本地 `applyConversationStreamCacheToDisplay()` 回填，因此工具运行中提示会在恢复时丢失。

## 目标

- 前台恢复当前流式会话时，synthetic draft 与实时流式 draft 保持同一套工具状态字段。
- 用户在窗口失焦、冻结或重新聚焦后，若工具仍在执行，界面继续显示正确的“运行中/完成/失败”工具状态。
- 改动尽量收敛在后端恢复投影构造处，不扩大前端恢复链路复杂度。

## 实施方案

1. 保持 `tool_status_text` / `tool_status_state` 继续作为后端流式缓存真源，不新增第二份缓存。
2. 在 `build_foreground_stream_projection_message()` 中，把缓存里的工具状态写入恢复消息 `provider_meta`：
   - `_toolStatusText`
   - `_toolStatusState`
3. 增加 Rust 单测，钉死恢复投影消息必须保留这两个字段。

## 实施结果

- 已在 `src-tauri/src/features/system/commands/config_and_persona/unarchived_conversations.rs` 中补齐恢复投影消息的工具状态字段写入。
- 已新增单测覆盖恢复投影消息的 `provider_meta` 字段保留行为。

## 验证

- 运行最小相关 Rust 测试：
  - `cargo test foreground_stream_projection --package easy-call-ai`
- 预期结果：
  - 恢复投影仍只保留单条 synthetic draft。
  - synthetic draft 的 `provider_meta` 包含 `_toolStatusText` 与 `_toolStatusState`。

## 风险与边界

- 本次不改实时 delta 主链，不改前端工具状态归一化逻辑。
- 本次不改 `stream_blocks` 语义，只补齐恢复投影与实时草稿之间缺失的元数据一致性。
