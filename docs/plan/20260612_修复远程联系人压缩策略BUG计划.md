# 修复远程联系人压缩策略 BUG 计划

## 需求
- 远程联系人会话新增一个自动压缩时机。
- 当远程联系人会话超过 10 小时没有发生 LLM 通讯时，在下一次再次激活 LLM 通讯前，先执行一次现成的正式压缩。
- 压缩完成后，再继续本轮正常调度。
- 这个能力只针对远程联系人会话，不扩展到普通本地会话。
- 压缩能力复用现有正式压缩方法，不重新设计新的压缩语义。

## 边界
- 本计划只处理“远程联系人会话何时自动触发现成压缩”这个问题。
- 本计划不讨论跨会话通知、消息转发、会话工具、block 设计、prompt 截窗设计。
- 本计划不新增新的压缩算法，只新增自动触发压缩的时机判断。
- “LLM 通讯”指会话真正进入一轮 LLM 调度，不是普通读写、分页、刷新、查看列表。
- “超过 10 小时未激活”指距上一次 LLM 通讯结束已经超过 10 小时。

## 之前的关键错误
- 把一个本来只是“新增远程联系人自动压缩时机”的需求，错误做复杂了。
- 错误引入了额外的业务日、最近有效段、临时 block 等语义。
- 错误把局部上下文视图混入正式历史链路，导致历史消息被破坏。
- 结果不是“压缩时机不对”这么简单，而是演变成了历史 block 数异常减少、旧消息损坏的严重问题。

## 钉死的需求
- 只新增一个规则：远程联系人会话超过 10 小时未发生 LLM 通讯时，下次激活 LLM 通讯前先压缩。
- 压缩调用现成正式方法，不允许再发明替代语义。
- 压缩后正常续跑，不允许引入额外的“临时段”“临时 block”“最近有效段”概念。
- 不允许因为这个功能改坏历史消息。
- 不允许把 prompt 局部视图、分页视图、最近消息段带入正式存储链路。
