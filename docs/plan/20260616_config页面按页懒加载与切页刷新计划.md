# Config 页面按页懒加载与切页刷新计划

## 需求

1. Config 窗口首屏启动时，不再顺手加载所有设置页的扩展数据。
2. 每个设置页只在用户实际切换到该页时触发该页自己的数据加载。
3. 同一个设置页在用户切走后再切回来时，应重新执行该页的数据加载，以便拿到更及时的数据。
4. “按页加载”覆盖的对象包括各页专属的动态数据、状态探测、统计信息、列表拉取、运行时查询，不只是不显示 UI。
5. Config 页签切换后的刷新语义要统一，避免有的页切回来会刷新，有的页仍沿用旧缓存。
6. 启动期仍允许保留 Config 窗口渲染所必需的最小公共数据，保证页面能正常显示和编辑。
7. 切页触发的加载过程要有明确的加载态，避免用户误以为数据已经是最新。
8. 懒加载改造后，现有显式刷新按钮仍然保留；“切页刷新”和“手动刷新”并存，且语义一致。

## 钉死边界

1. 这次只定义 Config 窗口的数据加载边界，不改 Chat 窗口、Archives 窗口的启动链路。
2. 这次不做“所有配置字段按页拆分存储/按页单独保存”；配置保存模型仍以现有全局配置对象为主。
3. 这次不要求把 `load_app_bootstrap_snapshot` 立即拆成完全独立的多接口；是否拆接口属于实现手段，不写进本计划目标。
4. 启动时仍可一次加载这些公共基础数据：
   - 配置主对象 `config`
   - 人格列表 `agents/personas`
   - 聊天设置 `chatSettings`
   这些数据当前被多个设置页共同依赖，且是页面框架可用的基础前提。
5. 本次重点收敛的是“页内附加运行时数据”和“页内二次查询”，例如工具状态、图片缓存统计、网络访问信息、存储统计、记忆页查询、日志页查询、任务页查询、MCP/Skill 运行态列表等。
6. 已经天然依赖 `v-if` 挂载、因此切页会重新 `onMounted` 的页面，不强行改成额外缓存机制；目标是统一按页进入时刷新，而不是引入新的常驻缓存层。
7. 不以“减少所有 IPC 次数”为目标；如果某页每次进入都重新查询是为了拿到最新数据，这属于预期行为。
8. 不为了懒加载去牺牲当前的可编辑体验：
   - 进入页面前不需要的数据可以不查
   - 进入页面后该页正常编辑所需的数据必须一次补齐
9. 不改变现有“显式保存为主、非 watch/autosave 为主”的配置页交互原则。
10. 不把页面切换刷新扩展成后台轮询、全局定时刷新、窗口激活自动全量重载；本次只钉死“切到页面时加载，切回来时再加载”。
11. 如果某些页面当前已经满足“切页即加载”，后续实现只需要保留该行为并纳入统一口径，不重复重构。
12. 这次计划不包含 UI 改版，只允许为加载态、空态、错误态补最小必要提示。

## 现状前提

1. 当前 `ConfigView.vue` 主要内容区已经使用 `v-if / v-else-if` 切换，大部分 tab 组件不是同时挂载。
2. 当前 Config 窗口启动时，`ConfigWindowApp.vue` 仍会统一执行一次 `load_app_bootstrap_snapshot`，并额外执行 `refreshImageCacheStats()`。
3. 当前已有部分页面是在各自 `onMounted` 中查询页内数据，例如 `MemoryTab`、`NetworkAccessTab`、`StorageTab`、`ToolsTab`、`McpTab`、`TaskTab`、`LogTab`、`RemoteImTab`、`AboutTab`、`WelcomeTab`。
4. 因此后续实现的核心不是“让所有 tab 首次才 mount”这一件事，而是把仍放在窗口级启动链路里的非公共数据，收回到对应页面的进入时机。
