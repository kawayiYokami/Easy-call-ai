# 20260609 部门执行上下文提示词解耦修复计划

## 一、问题结论

当前发现的风险不是 `leader` 预设部门本身，而是提示词与工具权限链路里存在错误依赖：

- `agent` 是人格。
- `department` 是部门 / 岗位。
- `conversation` 是消息容器。
- 当前模型调用必须先确定“本次调度部门”，再从该部门配置中解析本次执行人格。

因此以下推导都是错误的：

- 用 `agent_id -> department` 推导当前部门。
- 用 `conversation.department_id` 代表本会话内所有后续发言的当前部门。
- 用只包含 `agent_id` 的缓存 key 缓存部门提示词。
- 把 `agent_id` 当成调度源，再反向推导部门或权限。

这些错误会在“同一人格服务多个部门”时造成部门提示词、直属下级、工具规则或 skill 快照串部门。

## 二、不可变规则

### 1. 部门是调度源

所有模型调用都必须先确定调度部门：

- 用户主动聊天：来自本次发送请求选择的部门。
- 队列激活：来自 pending event 的 `ChatSessionInfo.department_id`。
- 委托线程：来自委托目标部门 `target_department_id`。
- 用户 @ 部门 / 手动委托：来自目标部门。
- 远程 IM：来自联系人绑定部门。
- 任务调度：来自任务调度指定的执行部门。

调度源不能是人格。

### 2. 人格由部门解析

本次执行人格必须从调度部门的配置中解析：

- 当前兼容阶段默认使用 `DepartmentConfig.agent_ids[0]`。
- 任何外部请求、前端 payload、队列事件、工具调用都不能通过 `agent_id` 指定或覆盖人格。
- 如果现有结构里仍带 `agent_id` 字段，该字段只能作为服务端按部门解析后的兼容输出。
- 输入侧不得读取 `agent_id`；兼容期结构体残留该字段时，服务端必须用部门解析结果覆盖它，不能消费调用方传入值。

人格提示词来自解析后的执行人格：

- `agent.system_prompt`
- 人格名称、头像、说话风格

人格不能决定当前部门，也不能决定调度路线。

### 3. 部门只管本次执行部门

部门提示词只来自本次调度部门：

- 部门办事指南
- 直属下级部门
- 部门工具权限
- 部门 skill 快照

部门来源必须是显式调度上下文，不允许从人格反查。

### 4. 会话只是默认入口与容器

`conversation.department_id` 只能表达“会话主入口 / 默认激活部门 / 旧数据兜底”。

它不能代表：

- 同一会话中所有部门发言的部门身份。
- 委托线程的目标部门。
- 用户 @ 某个部门后的目标部门。
- 队列中某个 pending event 的执行部门。

### 5. 当前执行上下文必须显式携带调度部门

凡是会触发模型调用的路径，都必须在调用前得到明确的调度部门：

- `executor_department_id`

现有结构里已经有可用载体：

- `SessionSelector.department_id`
- `ChatSessionInfo.department_id`
- `RuntimeContext.executor_department_id`
- 委托记录的 `target_department_id`
- 用户 @ 委托计划的 `target_department_id`
- 远程 IM 绑定部门
- 任务调度 executor department

执行人格由调度部门解析后写入现有兼容字段：

- `executor_agent_id`
- `SessionSelector.agent_id`
- `ChatSessionInfo.agent_id`

这些字段是“部门解析出的执行人格结果”，不是调度源，也不是调用方可传入的选择项。

修复目标是让提示词和工具组装统一读取显式调度部门，再使用该部门解析出的执行人格，而不是重新推断。

## 三、当前高风险点

### 1. 调度入口携带 `agent_id`

位置：

- `src-tauri/src/features/core/domain/types_requests.rs`
- `SessionSelector.agent_id`
- `RuntimeContext.executor_agent_id`
- `ChatSessionInfo.agent_id`

风险：

- 如果入口允许调用方传 `agent_id`，就可能绕过部门配置直接指定人格。
- 这会破坏“部门是调度源，部门解析人格”的模型。

修复：

- 输入侧只信任调度部门 id。
- `agent_id` / `executor_agent_id` 只能在服务端解析部门后生成。
- 当前兼容期如果结构体字段暂时不能删除，也必须把它视为派生字段；外部传入值不能参与调度决策。

### 2. 部门提示词块

位置：

- `src-tauri/src/features/chat/conversation.rs`
- `build_departments_prompt_block`
- `prompt_department_context_from_provider_meta`

风险：

- 当前代码通过 `department_for_agent_id` 取当前部门。
- 在同一人格挂多个部门时，会取到配置顺序中的第一个部门。

修复：

- 函数签名改为接收 `current_department_id`。
- 根据 `current_department_id` 查 `DepartmentConfig`。
- 找不到时返回错误或空块，由上层记录失败；不能偷偷用人格兜底。

### 3. 部门工具规则

位置：

- `src-tauri/src/features/chat/conversation.rs`
- `build_system_tools_rule_blocks`
- `department_builtin_tool_enabled`

风险：

- 工具规则按人格反查部门。
- 会导致 task / delegate / meme / exec 等工具规则和权限串部门。

修复：

- `build_system_tools_rule_blocks` 改为接收 `current_department_id` 或 `current_department`。
- 工具规则与权限只使用当前执行部门。

### 4. 部门 skill 快照

位置：

- `src-tauri/src/features/chat/conversation_prompt_service.rs`
- `build_internal_system_preamble_blocks`
- `build_hidden_skill_snapshot_block_for_department`

风险：

- skill 快照按人格反查部门。
- 私有组织或部门权限里的 skill 可能被错误注入。

修复：

- 从当前执行上下文解析 `current_department`。
- skill 快照只按该部门构建。

### 5. 部门提示词缓存

位置：

- `src-tauri/src/features/chat/prompt_manager.rs`
- `build_department_system_prompt_cache_key`
- `DepartmentSystemPromptCacheEntry`

风险：

- 缓存 key 只含 `agent + ui`。
- 同一人格被多个部门使用时，后一个部门会复用前一个部门的部门提示词。

修复：

- 部门提示词缓存 key 必须包含 `executor_department_id`。
- 缓存条目的 `department_id` 必须来自当前执行部门。
- 日志中的 department_id 也必须来自当前执行部门。

### 6. 最终系统提示词缓存

位置：

- `src-tauri/src/features/chat/conversation_prompt_service.rs`
- `finalize_system_prompt`

风险：

- 当前 final cache key 包含 `conversation_id + agent_id`，但不包含执行部门。
- 同一会话内多个部门轮流发言时可能复用错误最终系统提示词。

修复：

- final cache key 增加 `executor_department_id`。
- entry 的 `department_id` 来自执行部门。

### 7. 运行时工具组装

位置：

- `src-tauri/src/features/chat/model_runtime/provider_and_stream/tool_assembly.rs`
- `resolve_runtime_tool_current_department`

风险：

- 优先从 delegate runtime conversation / conversation 读取部门，最后用人格兜底。
- 这对同一会话多部门发言不够精确。

修复：

- 工具组装入口优先读取 `RuntimeContext.executor_department_id`，或从 tool session 解析到当前调度的执行部门。
- 如果拿不到显式执行部门，应拒绝部门受控工具或记录错误，不应从人格反查。

## 四、实施步骤

### 阶段 1：引入执行部门解析 helper

新增或收口一个 helper，例如：

```rust
fn resolve_execution_department<'a>(
    departments: &'a [DepartmentConfig],
    executor_department_id: &str,
) -> Result<&'a DepartmentConfig, String>
```

要求：

- 输入必须是显式 executor department id。
- 只负责查找和报错。
- 不接受 agent id。
- 不读取 conversation.department_id 作为“当前部门”。

### 阶段 2：提示词构建显式传参

调整以下链路，让当前执行部门从调度入口一路传到 prompt service：

- `SendChatRequest.session.department_id`
- `RuntimeContext.executor_department_id`
- `ChatSessionInfo.department_id`
- 委托运行的 `target_department_id`
- 用户 @ 委托计划的 `target_department_id`

同时收紧这些结构里的 `agent_id`：

- 输入侧不得信任调用方传来的 `agent_id`。
- 服务端先解析调度部门，再取该部门配置中的主执行人格。
- 需要兼容旧函数签名时，由服务端把解析结果填入或覆盖 `agent_id` 字段。

目标是 prompt 构建函数不再自行推断部门，也不从输入 `agent_id` 选择人格。

### 阶段 3：改部门提示词与工具规则

改造：

- `build_departments_prompt_block`
- `build_system_tools_rule_blocks`
- `build_internal_system_preamble_blocks`
- `build_prompt_snapshot`
- `finalize_system_prompt`

所有部门相关逻辑都读取同一个 `executor_department_id`。

### 阶段 4：修缓存 key

修复：

- Department prompt cache key：`scope + executor_department_id + agent_id + ui`
- Final system prompt cache key：`scope + conversation_id + executor_department_id + agent_id`

这里的 `agent_id` 必须是服务端从部门解析出的执行人格 id，不能是调用方输入值。

同时确保 mark dirty 按 department id 能命中对应缓存。

### 阶段 5：收紧错误兜底

对于部门受控提示词 / 工具：

- 缺少 executor department id 时，返回无部门上下文或明确错误。
- 不再使用 `department_for_agent_id` 作为当前部门兜底。

保留 `department_for_agent_id` 的合法用途：

- 旧数据迁移兜底。
- 无执行上下文的展示层兼容。
- 解析默认主入口时的临时兼容。

禁止它参与当前模型调用的部门提示词、工具权限和 skill 快照。

## 五、回归测试

必须新增以下测试：

1. 同一人格跨两个部门时，leader 调用注入 leader 的部门指南，而不是助理部门指南。
2. 同一会话内先后用两个部门触发模型调用，final system prompt cache 不串。
3. 同一人格跨两个部门时，部门 prompt cache 不串。
4. 工具规则按 executor department 判断：有下级的部门能看到 delegate 规则，无下级的部门不能看到。
5. skill 快照按 executor department 判断，不按人格所属第一个部门判断。
6. 委托线程使用 target department 作为 executor department。
7. 用户 @ 部门 / 手动委托入口使用 target department 作为 executor department。
8. 请求里伪造或传入不属于该部门的 `agent_id` 时，不能改变执行人格。

## 六、验收标准

- 搜索 `department_for_agent_id(`，确认不再出现在当前模型调用的提示词、工具权限、skill 快照路径中。
- 搜索调度入口，确认外部输入的 `agent_id` 不再作为执行人格选择依据。
- 搜索部门 prompt cache key，确认包含 executor department id。
- `leader` 与助理部门共用默认助理人格时，提示词不会串部门。
- 同一会话多部门轮流发言时，提示词不会复用上一个部门的缓存。
- 相关 Rust 单测通过。

## 七、非目标

本计划不做完整字段重命名：

- 不把所有 `agent_id` 立即改名为 `persona_id`。
- 不重做前端部门 / 人格配置 UI。
- 不重做历史消息数据结构。

本计划只修当前严重 bug：

- 当前模型调用的部门上下文必须来自显式执行上下文。
- 人格与会话都不能替代执行部门。
